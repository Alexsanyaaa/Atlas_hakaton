# Второй этап обучения на RX 9070 XT / WSL

Это дополнение к уже работающему проекту в WSL. Python, PyTorch ROCm и `.venv-wsl` переустанавливать не нужно. Старые модели и исходные данные сохраняются. Архив не содержит веса: используется ваш лучший checkpoint шага 20000.

## 1. Распакуйте дополнение

Откройте Ubuntu, где работало обучение. В командах ниже замените ВАШЕ_ИМЯ на имя пользователя Windows. Копируйте только содержимое блоков кода.

```bash
cd "$HOME/transformer_rx9070xt_demo"
unzip -o "/mnt/c/Users/ВАШЕ_ИМЯ/Downloads/transformer_refinement_v2.zip" -d .
.venv-wsl/bin/python verify_refinement_bundle.py
```

Архив обновляет код подготовки/обучения и добавляет отдельную папку `data/participant3_refined`. Файлы исходных train/dev/test и веса не перезаписывает. Для нового этапа используйте новый `run_refinement_wsl.sh`: старый `run_rx9070xt_wsl.sh` проверяет прежние хеши кода, которые после обновления изменятся.

## 2. Запустите вариант C

```bash
bash scripts/run_refinement_wsl.sh --variant C
```

Скрипт ищет единственный исходный `checkpoint` шага 20000 в `models` или папках `full-*` в корне. Если найти его однозначно не удалось, укажите путь явно. Например, если ваша модель лежит в `models/full-4164ed19-ddeb-4aaa-a8ee-c21c7d2d4ebc/checkpoint`:

```bash
bash scripts/run_refinement_wsl.sh --variant C --checkpoint "models/full-4164ed19-ddeb-4aaa-a8ee-c21c7d2d4ebc/checkpoint"
```

Важен именно `checkpoint`, а не `checkpoint-last`. Скрипт печатает новую папку результата вида `models/refinement_C_ДАТА_ВРЕМЯ`. Короткие A/B/C делают до 2000 новых шагов; максимум 3 часа на запуск, обычное окончание должно быть раньше. Это предохранитель, не оценка времени. Вариант может остановиться досрочно по dev. Начальные веса оцениваются и сохраняются до обучения.

## 3. Сравните остальные варианты

Запускайте по очереди. A — исправленная разметка, B — добавление сложных примеров, C — дополнительно другой LR и scheduler.

```bash
bash scripts/run_refinement_wsl.sh --variant A
bash scripts/run_refinement_wsl.sh --variant B
```

D обучается от исходного RuBERT, а не от ваших весов; использует весь исправленный train. Он потребует больше времени и может скачивать базовую модель, если её нет в кэше. Потолок — 6 часов.

```bash
bash scripts/run_refinement_wsl.sh --variant D
```

При повторном запуске каждый раз создаётся новая папка, старые результаты не заменяются. Это не продолжение прерванного optimizer/scheduler: новый запуск дообучается с исходной точки.

## 4. Проверьте сложные случаи

Вставьте реальный путь новой папки вместо `models/ВАША_НОВАЯ_ПАПКА`:

```bash
source scripts/rocm_wsl_env.sh
.venv-wsl/bin/python evaluate_refinement.py --device cuda --checkpoint "models/ВАША_НОВАЯ_ПАПКА/checkpoint" --output "models/ВАША_НОВАЯ_ПАПКА/challenge"
```

Этот маленький синтетический стресс-набор не является итоговой оценкой каталога и не участвует в выборе checkpoint. Помимо F1 смотрите `false_positive_negative_tasks`: сколько ответов появилось там, где характеристика явно отсутствует.

## 5. Таблица сравнения

Подставьте реальные пути запусков:

```bash
.venv-wsl/bin/python compare_refinement.py --runs "models/ПАПКА_A" "models/ПАПКА_B" "models/ПАПКА_C"
```

Получится `reports/refinement_v2/comparison.csv`. Скрипт не разрешает смешивать dev F1 с разными хешами датасета. Старые 0,9424 и новый dev F1 нельзя напрямую сопоставлять: разметка исправлена. В A/B/C есть начальная оценка на новом dev — сравнивайте прежде всего с ней, а между вариантами используйте одну версию dev и одинаковую длину окна.

## 6. Пороги после обучения

Подставьте папку всего запуска, не папку checkpoint:

```bash
.venv-wsl/bin/python diagnose_refinement.py --run "models/ВАША_НОВАЯ_ПАПКА" --source data/participant3_refined --output "models/ВАША_НОВАЯ_ПАПКА/threshold_diagnostics"
```

Получатся предварительные пороги для очереди ручной проверки. Они не включают автоприём и не калибруют вероятности. Старые пороги из дополнения относятся к исходным весам. Для надёжного автоприёма сначала нужна человеческая разметка с явным отсутствием характеристик и независимая оценка.

## 7. Что прислать

Для каждого запуска: `best_metrics.json`, `training_history.json`, `training_summary.json`, `run_config.json`, `data_manifest.json`, `dev_predictions.jsonl`; папки `challenge` и `threshold_diagnostics`, если выполнялись. `comparison.csv` тоже приложите. Веса достаточно прислать только у выбранного победителя, всей папкой `checkpoint`.

Подробности исправлений, исходная диагностика и ограничения: `reports/refinement_v2/README.md`. Данные и конфиги готовы, но GPU-варианты A/B/C/D ещё не обучены в этой среде.
