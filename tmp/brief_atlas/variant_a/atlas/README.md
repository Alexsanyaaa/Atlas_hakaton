# Атлас — проверка характеристик товаров

Рабочий инструмент контент-менеджера каталога: загрузить товары или текст, получить характеристики с цитатами
из текста, проверить предложения системы и выгрузить готовые карточки.

## Запуск

Сборка и интернет не нужны.

1. Откройте `atlas/index.html` двойным щелчком (Chrome, Edge, Firefox, Safari).
2. Или запустите локальный сервер из корня проекта и откройте http://127.0.0.1:8770:

```bash
python -m http.server 8770 --bind 127.0.0.1 --directory atlas
```

Изменения сохраняются в браузере. Вернуть всё к исходному состоянию после показа: меню «⋯» справа вверху →
«Восстановить исходный набор».

Файлы для показа импорта лежат в `atlas/samples/`: CSV (одна строка без названия — ошибка, одна с неизвестной
категорией), JSON, два TXT и `не_текст.txt` для ошибки «это не текстовый файл».

## Сценарий демонстрации (2–3 минуты)

1. **Каталог (20 с).** Полоса «Что сделать сейчас» показывает очередь: противоречия, новые предложения,
   новые поступления, последняя карточка. Введите в поиск «Samsung», выберите «Есть нерешённые поля» —
   под поиском видны активные фильтры и «Сбросить фильтры».
2. **Противоречие (30 с).** «Разобрать противоречия» → «Смартфон Xiaomi Redmi 13C»: в описании 4 ГБ RAM, в параметрах
   продавца 5 ГБ. Справа цитата со скобкой и источником, листание «1 из 2». Нажмите «Оставить «4 ГБ»» —
   статус карточки, прогресс и счётчик «Ждут решения» в шапке обновятся, выбор перейдёт к следующей проблеме.
   Тост «Отменить» возвращает решение.
3. **Сложные случаи (40 с).** Последовательно откройте:
   * «Кофемашина De'Longhi» → Цвет: «серебристый и белый», предложен только белый → «Дополнить»;
   * «Чайник Polaris PWK 1725CGLD» → Цвет: «GLD» — часть артикула → «Отклонить предложение»: появляется следующий
     кандидат «черный» из описания; Мощность «2,2 кВт» → «2200 Вт» (разные обозначения единиц);
   * «Чехол Deppa … для Samsung Galaxy A55» → Бренд «Samsung» стоит после «для» → отклонить → «Deppa»;
   * «Диван Hoff Атланта» → Вес: значения нет → «Подтвердить отсутствие» (отдельное действие, не отклонение).
4. **Карточка из текста (30 с).** «Добавить» → «Вставить текст» → пример «Диван без бренда» → «Сформировать
   карточку»: найдено 6 из 9 характеристик, бренд и вес оставлены пустыми. Исправьте значение и создайте карточку.
5. **Автоматизация (15 с).** Процент автоматизации с числителем и знаменателем, распределение полей
   (автоматически / человеком / ждут решения), путь поля от текста до выгрузки, правила автоприёма.
6. **Аналитика и подходы (25 с).** Фильтр периода и категории; блок «Качество моделей» отдельно от операционных
   показателей. «Четыре подхода» → выбрать карточку → что нашёл каждый подход, пропуски, расхождения, источники.
7. **Выгрузка (10 с).** Каталог → статус «Готово к выгрузке» → выбрать все → «Выгрузить» → JSON или CSV. В файле
   у каждого значения указано «автоматически» или «человек»; у исправленных вручную нет оценки модели.

## Реализованные механики

**Каталог.** Поиск по названию, артикулу и бренду; фильтры по категории (с группами), статусу и проблемам;
активные фильтры с удалением по одному и общим сбросом; сортировка (требующие внимания, недавние, по названию,
по заполненности); выбор нескольких карточек и выбор всех показанных; массовые действия: обработать новые,
принять значения, подтверждённые текстом, выгрузить готовые, удалить (с отменой); фильтры сохраняются при
возврате из карточки и между перезагрузками; переход к предыдущей и следующей карточке списка; быстрые действия
«Разобрать противоречия», «Проверить новые предложения», «Обработать поступления», «Продолжить последнюю карточку».
Статус карточки (5 статусов) отделён от состояния каждой характеристики (8 состояний).

**Проверка характеристик.** Исходный текст (заголовок, описание, параметры продавца) с подчёркнутыми найденными
фрагментами и номерами характеристик; клик по фрагменту выбирает характеристику. Для выбранной характеристики:
значение, исходное и нормализованное написание, блок цитаты со скобкой и выделенным значением, источник,
листание нескольких источников, оценка модели с пометкой «уверенность, не точность», рекомендация с причиной,
действия. Рекомендации: принять, нормализовать, дополнить, требуется проверка (расхождение), отклонить, нет данных.
Действия: принять, исправить (с проверкой формата числа и выбором из справочника), отклонить предложение
(показывается следующий кандидат, характеристика не считается отсутствующей), подтвердить отсутствие,
выбрать одно из противоречащих значений, изменить решение. Отмена последнего действия, «Следующая проблема»
(внутри карточки, затем следующая карточка списка), смена названия и категории (с повторной подготовкой).
Подготовленные сложные случаи: два цвета, артикул вместо цвета, 4 и 5 ГБ RAM, «2,2 кВт» и «1,97 м»,
бренд совместимого устройства, действительно отсутствующая характеристика.

**Добавление.** Импорт CSV и JSON: выбор файла и перетаскивание, проверка формата и размера, предпросмотр строк,
сопоставление колонок с названием, описанием, категорией и артикулом, ошибки обязательных полей и дублей,
подтверждение, опция «сразу обработать», новые товары в каталоге. TXT: проверка типа и кодировки, просмотр
и правка текста, формирование карточки. Вставка текста: тот же сценарий без файла, примеры. Черновик: предложенные
название, категория и характеристики с цитатами, правка любого поля, выбор категории, если её не удалось
определить. Состояния: пустой ввод, неверный файл, чтение, обработка по шагам, частичный результат, успешное
создание, ошибка.

**Автоматизация.** Доля полей, принятых автоматически, с числителем и знаменателем; распределение полей по
решениям; путь поля от текста до выгрузки; правила автоприёма; разбивка по категориям; фильтр по группе.

**Аналитика.** Фильтры периода и категории; готовые и оставшиеся карточки; карточки, ставшие готовыми, по дням;
ручная работа по категориям; характеристики, которые чаще исправляют, отклоняют или не находят; проблемные
категории; доля автоматизации. Качество моделей (Precision, Recall, F1) — отдельный блок с контекстом оценки.

**Словари.** Цвета, бренды, единицы (с множителем), материалы, синонимы характеристик; поиск, фильтр по типу,
добавление, правка, удаление, проверка повторов, отмена; предпросмотр применения правил к примеру. Обработка
новых карточек сразу использует изменённые словари.

**Четыре подхода.** Объяснение подходов простым языком, выбор карточки, таблица результатов каждого подхода
(значения, пропуски, расхождения, лишние значения, источники), сравнение по качеству, скорости, стоимости и
обучению с контекстом каждого числа.

**Общее.** Сохранение в браузере, восстановление исходного набора, выгрузка JSON и CSV с разделением
автоматических и ручных решений, адаптивная вёрстка без горизонтальной прокрутки страницы, клавиатурный фокус.

## Технические ограничения (для презентации, в интерфейсе их нет)

* Это фронтенд без сервера и без подключения моделей. Подготовка характеристик в интерфейсе — локальная
  детерминированная обработка (`js/engine.js`): словари, шаблоны чисел с единицами, проверка контекста
  («для …», «до …», «без …»), сравнение с параметрами продавца. Она воспроизводима: одинаковый текст даёт одинаковый
  результат, а значения, которых нет в тексте, остаются пустыми.
* «Оценка модели» в карточках вычисляется этой обработкой по источнику и контексту фрагмента. Это не выход
  обученной модели. Порог автоприёма — 0,9.
* Каталог синтетический: 127 товаров 17 категорий и история решений за ~45 дней порождаются генератором
  (`js/seed.js`) с фиксированным зерном. Шесть сложных случаев написаны вручную (карточки h1–h6).
* Числа в блоке «Качество моделей» — реальные результаты оценки CRF-NER и словарных правил этой команды на
  отложенной выборке каталога М.Видео (78 414 карточек, отчёт `reports/catalog_metrics.md`, и 3 245 карточек
  для модели на 4 категории). Они не пересчитываются в интерфейсе.
* Страница «Четыре подхода»: результаты по четырём карточкам подготовлены вручную для иллюстрации различий
  подходов, это не эксперимент. Трансформер и LLM на этой выборке не оценивались — так и написано на странице;
  их скорость помечена как ожидание.
* Данные хранятся в `localStorage` этого браузера. Совместной работы, пользователей и прав нет.
* Импорт: файлы до 2 МБ, CSV с разделителем «;», «,» или табуляцией, JSON — массив объектов.

## Проверенные сценарии

| № | Сценарий | Результат |
|---|---|---|
| 1 | Найти товар и отфильтровать проблемные карточки | поиск по названию, бренду и артикулу; фильтр «Есть нерешённые поля»; фильтры сохраняются после возврата из карточки |
| 2 | Открыть характеристику и увидеть подтверждение | цитата со скобкой, источник, листание источников |
| 3 | Принять, исправить и отклонить разные предложения | статус поля, прогресс, статус карточки и счётчик в шапке обновляются; отмена работает |
| 4 | Подтвердить отсутствие характеристики | отдельная кнопка; поле «Отсутствует в тексте» |
| 5 | Создать карточку из вставленного текста | 7 из 7 для кофемашины; 6 из 9 для дивана без бренда; неизвестный текст — частичный результат |
| 6 | Создать карточку из TXT | неверный тип файла — понятная ошибка; смартфон HONOR — 8 из 8 |
| 7 | Импорт CSV/JSON с предпросмотром | 7 из 8 строк, строка без названия отклонена; битый JSON — номер строки |
| 8 | Выгрузить подтверждённые данные | 60 карточек; решения «автоматически» и «человек»; у исправлений нет оценки |
| 9 | Изменение показателей автоматизации | после решений меняются процент, распределение и «Ждут решения»; исправленное человеком автоматическое поле перестаёт считаться автоматическим |
| 10 | Сравнить четыре подхода на одном товаре | таблица для 4 карточек и сравнение по 4 критериям |

Ширина 375 px и 1366 px: горизонтальной прокрутки страницы нет ни на одном экране.

## Структура

```
atlas/
  index.html            оболочка и подключение скриптов
  css/atlas.css         стили: токены, состояния, адаптивность
  js/dict.js            словари нормализации по умолчанию
  js/schema.js          категории и характеристики
  js/engine.js          локальная обработка текста → кандидаты, цитаты, рекомендации
  js/model.js           карточки, решения, статусы, метрики
  js/seed.js            исходный каталог и история
  js/samples.js         примеры для страницы «Добавить»
  js/approaches.js      подготовленные результаты четырёх подходов
  js/app.js             состояние, маршруты, отмена, выгрузка, общие элементы
  js/view-*.js          экраны
  samples/              файлы для показа импорта
```
