# Атлас: извлечение характеристик товаров

Текущий этап — улучшение RuBERT и выбор интерфейса общего продукта. Правила/словари и CRF пока представлены результатами команды; полные реализации ожидаются. LLM — будущий необязательный модуль.

Временные сборки, старые CPU-модели, предыдущие архивы и дубли инструкций убраны из проекта в системную корзину. Исходные данные, окружение `.venv`, Git-история и все три исходника сайтов сохранены.

## Запуск следующего обучения

В уже настроенном WSL-окружении:

```bash
cd "$HOME/transformer_rx9070xt_demo"
bash scripts/run_refinement_wsl.sh --variant C
```

Скрипт автоматически ищет единственный исходный checkpoint шага 20000. При необходимости укажите его явно:

```bash
bash scripts/run_refinement_wsl.sh --variant C --checkpoint models/transformer/checkpoint
```

- **A:** исправленная разметка, постоянный LR 2e-5.
- **B:** A + сложные примеры.
- **C:** B + LR 1e-5, warmup 6%, линейное снижение LR.
- **D:** новое обучение с исходного RuBERT на всей исправленной выборке.

A/B/C — до 2000 новых шагов с исходного лучшего checkpoint; D — до трёх эпох. Каждый запуск сохраняется в новую папку `models/refinement_*`. Начальная модель в A/B/C оценивается до обучения и остаётся лучшей, если дальнейшее обучение ухудшает F1. Победитель между A/B/C/D пока не определён: полного GPU-сравнения ещё не было.

[Подробная инструкция WSL и сравнение запусков](output/ИНСТРУКЦИЯ_УЛУЧШЕНИЕ_ТРАНСФОРМЕРА_V2.md) · [Диагностика и ограничения](reports/refinement_v2/README.md)

Для первоначальной установки на Windows 11 + RX 9070 XT нужны WSL2 Ubuntu 24.04, Python 3.12 и драйвер AMD в Windows. В Ubuntu подготовьте пакет:

```bash
sudo apt-get update
sudo apt-get install -y python3 python3-venv python3-pip bash unzip
bash scripts/setup_rx9070xt_wsl.sh
```

Установщик ставит закреплённые ROCm/PyTorch и проверяет GPU. Он предназначен для этой конкретной конфигурации; уже работающее окружение переустанавливать не требуется. Для свежего обучения без старых весов используйте вариант D.

## Что означает текущее качество

Исходный лучший checkpoint: micro span F1 **0,9424** на автоматически сформированной silver-разметке. Это не доля полностью правильных карточек. В новой версии исправления затронули 3317 train и 396 dev записей; добавлены 107 синтетических обучающих и 23 диагностические задачи. Исправления выполнены по явной политике схемы и не являются индивидуальными человеческими подтверждениями.

Пороги в `reports/refinement_v2/*review.yaml` предварительные, относятся к исходным весам и исходной разметке. У всех `auto_accept: false`. После переобучения нужны повторная диагностика и независимая человеческая проверка. Test не используется при подборе. Обучение, нормализацию значений и качество всей карточки оцениваем раздельно.

## Проверка и перенос

```bash
.venv/bin/python -m pytest -q tests/transformer
.venv/bin/python scripts/package_refinement.py
.venv/bin/python verify_refinement_bundle.py
```

На GPU-ПК вместо `.venv` используется `.venv-wsl`. Сборщик обновляет текущий ZIP, не создавая цепочку копий. Проверка хешей относится к готовому архиву; после редактирования его исходников сначала пересоберите пакет.

Для диагностики исходных весов:

```bash
.venv/bin/python diagnose_refinement.py --run models/transformer --source data/participant3_demo --output reports/refinement_v2
```

Ручная разметка: откройте `output/manual_review/review.html`, отметьте все вхождения/отсутствие, сохраните JSON. Это dev-аудит для разбора ошибок, не независимый финальный test. Инференс для этих карточек:

```bash
.venv/bin/python review_transformer.py predict --checkpoint models/transformer/checkpoint --cards output/manual_review/cards.jsonl --output output/manual_review/predictions.jsonl
```

## Единый продукт и недорогой запуск

Предварительный гибрид: правила обрабатывают простые поля, CRF — оставшиеся, трансформер — сложные. Порядок подтвердим общим сравнением. Необязательно запускать все методы для каждого товара. Нормализация и формат результата общие: атрибут, исходное/нормализованное значение, единица, метод/версия, цитата и смещения, оценка уверенности и решение человека.

Для старта: один backend с подключаемыми модулями, фоновый обработчик, общая база и кэш по содержимому/категории/версиям модели и словаря. CPU — первый кандидат для обслуживания, но ресурсы RuBERT определяем замерами. Сравниваем качество, скорость и полную стоимость: вычисления, ручная проверка и поддержка.

В будущем интерфейсе нужны режим «Гибрид», происхождение значений, раскрываемые альтернативы, отдельные действия принять/исправить/отклонить/не найдено. Конфликт не разрешается простым голосованием; оценки разных методов не усредняются напрямую. Аналитика учитывает качество автоприёма и ручной труд.

LLM выключена по умолчанию. Предусмотреть выбор модели/поставщика, разрешённые поля, бюджет, лимит запросов, таймаут и обработку ошибок. Без LLM основные методы работают самостоятельно. Ключи хранятся только на сервере. Реализация LLM и общая интеграция первых двух методов пока не выполнены.
