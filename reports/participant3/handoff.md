# Передача участника № 3

Подготовлен новый демонстрационный комплект `output/transformer_rx9070xt_demo.zip`: 39 999 товаров, 195 912 положительных пар, 394 поддержанных train-полями характеристики из 87 разделов. Быстрый trainer ограничен 128 характеристиками, 30 000 train-парами, 1200 шагами и мягким лимитом 6 часов. Инструкция — `README_RX9070XT.md`; для AMD RX 9070 XT под Windows 11 используется WSL2 Ubuntu 24.04, потому что нативный ROCm 7.2.1 не поддерживает ML training. `data/participant3_demo/attribute_registry.json` содержит новые стабильные проектные ID по фактическим именам параметров; это ещё не общий официальный semantic schema. Данные — ограниченный префикс со слабой разметкой; итоговая gold-оценка и общая нормализация по-прежнему нужны. Одинаковые нормализованные названия и описания от 80 символов объединены со связанными вариантами моделей до split. Старые CPU-пилоты ниже относятся к прежнему набору, не сравнивать их F1 напрямую с новым запуском.

Дополнение по категориям: `output/team/Основные_характеристики_96_разделов.md` и одноимённый JSON содержат рабочие основные характеристики для всех 96 корневых разделов реального дерева. Это руководство по разделам, не готовая runtime-таксономия 5788 конечных категорий. Для № 1: уточнить применимость на уровне подкатегорий, назначить стабильные ID и типы, проверить поддержку по всему каталогу; для № 2: общие единицы, смысл и множественность значений. Подтверждение параметров в первых 5000 карточках отдельно сохранено в `reports/participant3/section_parameter_audit.json`. Существующие checkpoint обучались только на прежних восьми ID; расширение документа не означает расширение обученной модели.

Готово: фактический аудит данных, ограниченный безопасный адаптер, условная BIO-подготовка без подачи catalog targets модели, настоящее CPU-дообучение ruBERT-tiny2, сохранённый проверенный checkpoint, частичное CPU-дообучение ruBERT-base и полный GPU-конфиг, standalone extractor, общий resolver и политика confidence. Читайте README_PARTICIPANT_3.md и reports/transformer_experiment.md.

№ 1: data/participant3/manifest.json — только временный prefix split. Нужен общий официальный/согласованный список обязательных атрибутов, репрезентативная выгрузка и evaluator canonical values. Query clicks — не extraction gold. Не включать большие приватные файлы в Git/архив исходников.

№ 2: data/participant3/spans.jsonl — слабые совпадения, не ручной gold. Источник/поле/позиции сохранены, unknown не превращён в отсутствие. Для общего CRF-сравнения согласовать attribute-conditioned постановку либо дать полную BIO-разметку. Normalize/semantic grounding остаются в вашей области. Перед resolver кандидат должен иметь value, unit, normalization_id и проверенную evidence. Review queue: outputs/participant3/review_queue.jsonl.

№ 4: подключить TransformerExtractor.extract(card, schema, requested_attributes); выход — словари контракта v2. При необходимости конвертируйте в ваши общие Pydantic-типы. Артефакт CPU models/participant3_cpu/checkpoint; для основной GPU-модели — configs/transformer.yaml. Модель не использует rules/LLM fallback. Не маркировать review как автоматически заполненное значение. Checkpoint и tokenizer нужно переносить целиком вместе с task_metadata.json. Сохранённый CPU checkpoint не является обученным ruBERT-base.

Git-репозитория в текущей папке нет, поэтому ветка/коммит не создавались. Создан общий Python-каркас; при интеграции сохраните зависимости других участников. source-only архив содержит код/конфиги/отчёты, но не исходные данные и веса.

Дополнительно: модели ai-forever/ruBert-base действительно дообучены на CPU с разморозкой последних двух encoder-слоёв; основной из этих пилотных checkpoint — models/participant3_rubert_pilot/checkpoint. Его silver span-F1=0.3333, precision=0.28, support=51. Это не заменяет полный GPU-прогон и не сравнимо напрямую с tiny2 из-за разных подвыборок. Все исходные .bin веса загружались weights_only=True, результаты сохранены в safetensors. Очередь ручной проверки исключает группы всех выполненных запусков.
