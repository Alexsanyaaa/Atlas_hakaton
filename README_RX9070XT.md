# Быстрый тестовый checkpoint: RX 9070 XT, Windows 11 + WSL2

Перенесите весь архив `transformer_rx9070xt_demo.zip` и распакуйте в новую папку `transformer_rx9070xt_demo`. В этой папке должны непосредственно лежать `train_transformer.py`, этот README и каталоги `data`, `src`, `scripts`. Один `train_transformer.py` без модулей, конфига и подготовленных данных не запустит обучение. Исходные `skus.pkl`, Parquet и `query_clicks` для этого запуска на втором ПК не нужны.

## Что обучаем

Дообучается encoder `ai-forever/ruBert-base`, revision `05f37a2ca9e333fd18f30cd0c96c68d274793c69`, с новой головой token classification. Модель получает название характеристики, категорию и исходный текст, затем выделяет значение с точными позициями. Это участник № 3, не обучение LLM.

Подготовлены положительные пары «текст — известная характеристика» из каталожных параметров. Vendor/model/param служат источником слабой разметки и не подаются как скрытый ответ модели. Входы обучения — название и описание. Клики не используются. Пропущенные или неизвестные характеристики не превращаются в отрицательные примеры.

Данные взяты из ограниченного начала каталога, а не из равномерной выборки всего каталога. Названия новых характеристик взяты из фактически наблюдавшихся параметров с исключением рекламных/служебных полей. Синонимы `_search` объединены; остальные новые имена сохранены раздельно со стабильными ID `catalog_...`. Это ещё не полностью согласованная семантическая таксономия конечных категорий. Конфликтующие конкретные числовые target-значения исключаются. Полный отчёт — `data/participant3_demo/dataset_complete.json`, словарь — `attribute_registry.json`.

## Установка: Windows 11 с Ubuntu в WSL2

Обучение запускается **в Ubuntu 24.04 внутри WSL2**. Windows остаётся основной ОС. Нативный Windows PyTorch ROCm 7.2.1 не поддерживает ML training: наличие карты в таблице совместимости само по себе не означает поддержку обучения. Trainer явно отклоняет такой нативный запуск.

Выбран фиксированный набор: Python **3.12**, ROCm **7.2.1**, официальный Linux-wheel PyTorch **2.9.1**, ROCDXG **1.2.0**, режим **FP16**. Документация AMD для этого пути указывает Windows-драйвер Adrenalin **26.2.2** с поддержкой WSL2; сам скрипт Windows-драйвер не меняет. Это выбранный воспроизводимый выпуск, не утверждение о самой новой версии.

Источники: [ограничение обучения в нативной Windows](https://rocm.docs.amd.com/projects/radeon-ryzen/en/docs-7.2.1/docs/limitations/limitationsrad.html), [AMD: WSL2, ROCDXG и ML training](https://rocm.docs.amd.com/projects/radeon-ryzen/en/latest/docs/install/installrad/wsl/howto_wsl.html), [ROCDXG: установка и совместимость RX 9070 XT](https://github.com/ROCm/librocdxg), [официальные PyTorch wheels](https://rocm.docs.amd.com/projects/radeon-ryzen/en/docs-7.2.1/docs/install/installrad/native_linux/install-pytorch.html).

1. Установите подходящий Windows-драйвер AMD по WSL-инструкции выше.
2. В PowerShell от имени администратора установите WSL2 с Ubuntu. Если Ubuntu-24.04 уже установлена, повторная установка не нужна:

```powershell
wsl --install -d Ubuntu-24.04
wsl --update
```

Перезагрузите ПК, если Windows попросит. Откройте Ubuntu и создайте Linux-пользователя при первом запуске. [Инструкция Microsoft по WSL](https://learn.microsoft.com/en-us/windows/wsl/install).

3. Распакуйте архив и перенесите всю папку `transformer_rx9070xt_demo` в домашнюю папку Ubuntu. Например, если архив распакован в Windows Downloads, в терминале Ubuntu выполните команды, заменив `ВАШЕ_ИМЯ` на Windows-имя пользователя:

```bash
cp -r "/mnt/c/Users/ВАШЕ_ИМЯ/Downloads/transformer_rx9070xt_demo" "$HOME/"
cd "$HOME/transformer_rx9070xt_demo"
python3 verify_training_bundle.py
bash scripts/setup_rx9070xt_wsl.sh
```

Лучше работать в Linux-файловой системе, а не обучать непосредственно из `/mnt/c`. Если такая папка уже существует после прошлого запуска, используйте отдельную новую папку; не копируйте поверх результатов обучения.

Установщик ставит userspace ROCm и ROCDXG в WSL, создаёт отдельную `.venv-wsl`, устанавливает Linux AMD wheels и зависимости. Linux kernel/display driver внутрь WSL не ставится: графический драйвер остаётся в Windows. В конце выполняется реальное FP16-вычисление с backward и шагом AdamW. В API PyTorch AMD также называется `cuda`: это корректно, `torch.version.hip` должен быть заполнен.

На этом ноутбуке проверен CPU-путь кода и синтаксис shell-скриптов, но AMD GPU/WSL здесь нет. `check_gpu.py` должен завершиться `fp16_backward: PASS` на целевом ПК. Автоматического запуска обучения после установки нет; отдельная команда запуска ещё раз проверяет GPU.

## Запуск

Сначала проверьте целостность подготовленного комплекта, затем запустите обучение:

В терминале Ubuntu из папки проекта:

```bash
bash scripts/run_rx9070xt_wsl.sh
```

Первый запуск скачает закреплённые pretrained-веса и tokenizer с Hugging Face. Если доступ к сети ограничен, заранее загрузите этот snapshot и укажите локальную папку в поле `model` конфига. В архиве нет pretrained-весов или старых CPU checkpoint.

Основной конфиг — `configs/rx9070xt_demo.yaml`:

| Параметр | Значение |
|---|---|
| Максимум выбранных train-пар | 30 000 |
| Характеристик в быстром режиме | Не более 128 поддержанных данными |
| Балансировка | Сначала по характеристикам, затем по разделам |
| Максимальная длина | 192 токена, длинные тексты разбиваются на окна |
| Microbatch / accumulation | 12 / 2, эффективный batch до 24 окон |
| Точность | FP16, без BF16 и без обязательных Flash Attention/Triton |
| Максимум шагов AdamW | 1 200 |
| Ограничение времени | 6 часов от старта функции, проверка между шагами |
| Сохранение и dev-проверка | Каждые 200 шагов и при завершении |
| Дополнительная остановка | 3 проверки dev без улучшения |

Режим предназначен для checkpoint за один рабочий день. Фактическая скорость зависит от ПК и установленных драйверов. Через 25 шагов выводится оценка оставшегося времени. Лимит времени мягкий: скачивание/подготовка не прерываются посреди операции, финальная проверка и запись могут добавить время. Время установки и скачивания заранее не измерено на вашем ПК. При необходимости уменьшите `max_steps` до 400–600. При нехватке видеопамяти уменьшите `batch_size` и `eval_batch_size` до 6, увеличьте `gradient_accumulation` до 4.

Обучение выполняется полностью на GPU; Dataset/токенизация и чтение файлов — на CPU. Отключать checkpointing для первого запуска не требуется.

Можно остановить процесс Ctrl+C: после завершённых шагов он попытается сохранить веса и завершить dev-проверку. При падении питания или закрытии процесса гарантируется только уже записанный периодический checkpoint. Этот демонстрационный trainer сохраняет веса, а не полный optimizer-state для точного resume; новый запуск начинается от pretrained-модели и требует новой папки `output`.

## Что забрать после обучения

- `models/rx9070xt_demo/checkpoint/` — лучший по dev checkpoint, tokenizer и `task_metadata.json`;
- `models/rx9070xt_demo/checkpoint-last/` — последние сохранённые веса;
- `best_metrics.json`, `training_summary.json`, `data_manifest.json` и `reload_verification.json` в папке запуска — фактические результаты и проверка загрузки.

Переносить нужно всю папку checkpoint целиком. `model.safetensors` без tokenizer и task metadata недостаточен для нашего извлекателя. Уже существующий checkpoint по умолчанию не перезаписывается.

## Демонстрация результата

```bash
bash scripts/run_rx9070xt_wsl.sh predict
```

Скрипт обрабатывает пять dev-карточек, запрашивая бренд, модель и цвет, и пишет `outputs/demo_predictions.jsonl`. Для других полей укажите ID из `attribute_registry.json`:

```bash
bash scripts/run_rx9070xt_wsl.sh predict --attributes brand model color storage_gb ram_gb
```

Извлекатель использует названия новых характеристик из task metadata checkpoint. Поддержка остальных ID появится только если они попали в обучение. В выводе сохраняются исходные фрагменты и raw score. Это не калиброванная вероятность и не автоматическое подтверждение правильности.

## Границы тестового результата

Train/dev/test разделены по приближённым группам моделей/вариантов, дополнительно объединены совпадающие нормализованные названия и описания от 80 символов; одинаковые примеры дедуплицированы. Обучающий скрипт не открывает test. Оценка dev — exact span-F1 по положительным парам слабой разметки, не качество всего каталога и не оценка отсутствующих значений. Для итогового сравнения с CRF/rules/LLM нужны общий согласованный split, семантическая нормализация и отдельно проверенный эталон. Старый пилот на 5000 товаров и текущий набор напрямую по метрикам не сравниваются.

## Увеличение данных позже

В проект включён инструмент `catalog_ai.participant3.full_corpus`: `--limit-offers 50000` строит ограниченный пилот, `--limit-offers 0` читает весь каталог с дисковым memo. Для переподготовки нужны исходные `cu_ws`, `pyarrow` и новый output-каталог. Это отдельная долгая операция и не выполняется при запуске `train_transformer.py`. Старые данные этим запуском не перезаписываются.
